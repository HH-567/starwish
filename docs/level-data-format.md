# 关卡与数据格式

v2 · 2026-11-02。表里的数值都是初值，原型跑起来后再调。状态和规则见 [状态机](state-machines.md)。
v2 写进了 11-02 补充的设定：职业和帮助、隐藏人物、可以不救人、去掉速度解锁、两个结局。11-02 晚补上终章场景、帮助点、路灯、隧道、逃离点和追逐的数值。

## 0. 已确认的决定

- 截止 2026-11-11，单人开发；首通目标 10–15 分钟（暂定）。
- 光常亮，两种模式切换：左键/空格 = 散射，右键/Shift = 聚光；触屏点按切换。
- 阶段 2 撞墙扣一大块亮度，亮度不够才碎裂。
- 虫洞可以保持速度方向，也可以把方向改成出口朝向。
- 回程赛道藏在各章场景里（关卡区上方或下方），终章把各章赛道首尾相接拼成一条路。
- 照亮 = 带来希望。借脑叶公司"光之种计划"的意思：光唤醒人心里的愿望。只借意思，不用原作的名字和画面。被照亮的人梦想浮现，之后用自己职业的方式帮小星（第 7 节）。
- 没有必救的人。可以一个都不救直接往前走，出口一直开着；代价是亮度上限不涨、终章没人帮。
- 没有速度解锁，也没有封顶。能到哪一档全看地图：直道有多长、有没有加速带（第 11 节）。这是游戏的核心；阶段阈值可以按关卡需要调。
- 隐藏人物在章内回头找：向导让藏着的人出声，锁匠打开铁门，邮差远程点亮小星照不到的人。
- 两个结局。正常结局：逃离噬光者，一个都不救也会进。隐藏结局：照亮所有人才触发，科学家打开虫洞 → 撞碎噬光者 → 在它体内找到电灯泡设计图 → 大家一起照亮全世界。

## 1. 文件布局

沿用现有的 `scenes/` + `scripts/` 分法：

```text
data/tuning.tres               全部数值（Tuning 资源）
data/tiles.tres                TileSet：32px，物理层 0 = 黑墙，遮光层 0；图块 0 = 墙，图块 1 = 边界（自定义数据 unbreakable）
scenes/levels/ch0_fall.tscn    序章；ch1_vine / ch2_mirror / ch3_crack / ch4_pair 同理
scenes/levels/finale.tscn      终章：开头（Intro）和结尾（Outro），中间的赛道运行时从各章接上（finale.gd）
scenes/entities/*.tscn         小星、小人、墙、道具、噬光者
scenes/ui/                     HUD、标题（主场景）、暂停菜单、结局；触屏控件之后加
scripts/autoload/game.gd       流程状态机 + 全局信号
scripts/autoload/save.gd       存档与进度
scripts/data/tuning.gd         Tuning 资源类
scripts/entities/、scripts/levels/（chapter.gd 是所有章节场景的根脚本，finale.gd 是终章的根脚本）
scripts/fx/                    碎片特效、光照工具（lighting.gd）、梦想浮现的占位画（dreams.gd）
tools/                         测试关和终章的生成器 build_test_levels、截图工具 shots / shots_ui / shots_finale；不打进导出包
tests/                         无头测试；不打进导出包
```

章节顺序写在 `game.gd` 的常量里：`CHAPTERS = [["ch0", "res://scenes/levels/ch0_fall.tscn"], ...]`。

## 2. 章节场景

```text
Chapter (Node2D, chapter.gd)     export chapter_id: StringName
├─ Level                         平时玩的关卡区
│  ├─ Walls (TileMapLayer)       黑墙
│  ├─ Entities                   小人、裂纹墙、玻璃、栅栏、铁门、软垫、虫洞、小星星…，可再分组
│  ├─ Checkpoints                1–2 个检查点
│  ├─ PlayerStart (Marker2D)
│  └─ Exit
└─ ChaseLane                     回程赛道，放在 Level 外的上方或下方
   ├─ Walls (TileMapLayer)
   ├─ Entities                   加速带、帮助点、可撞碎的杂物
   ├─ Entry (Marker2D)           进入点，也是终章的检查点
   └─ Exit (Marker2D)            离开点
```

- 场景实例化后、加入场景树前调用 `chapter.prepare(mode)`，删掉用不到的子树：普通模式删 ChaseLane，终章模式删 Level。没进树的节点不参与物理和渲染，平时完全碰不到赛道。
- 普通模式的镜头范围 = `Level/Walls.get_used_rect()`。
- 赛道约定：从右往左跑（回程）。Entry 在最右边缘、Exit 在最左边缘且同高，赛道全部内容的 x 坐标都在两者之间，这样拼起来各段首尾相接、不会重叠。两头的通道要敞开（没有边界墙），各段通道的高度对得上。
- 每段赛道的 Entry 后面放一条常亮加速带（不挂在帮助点下面），保证一个都没救也能跑完（但很难）。
- 帮助点（HelpPoint）用 NodePath 指向 Level 里的小人。`prepare(FINALE)` 删掉 Level 之前，先让它记下那个小人的 save_id 和职业。路灯、花、光门、隧道都是帮助点的子节点，人没救就跟着帮助点一起不出现。
- 赛道比屏幕矮也没关系：终章的镜头上下各多留 240 px，赛道外是背景色的暗处。

终章场景：

```text
Finale (Node2D, finale.gd)       存档 id 前缀是 finale
├─ Intro                         开头：噬光者在这里醒来
│  ├─ Walls、Entities
│  ├─ PlayerStart、BossStart (Marker2D)
│  └─ Exit (Marker2D)            第一段赛道的 Entry 对齐到这里
├─ Outro                         结尾：运行时挪到最后一段赛道后面
│  ├─ Walls
│  ├─ Entities                   逃离点（EscapePoint）；科学家的帮助点（everyone），下面是掉头虫洞
│  └─ Entry (Marker2D)           对齐最后一段的 Exit，也是检查点
└─ 运行时加上：各章（终章模式，只剩 ChaseLane）、噬光者、小星、HUD、暗处
```

- 各章按章节表倒序接上（ch4 → ch0）。章节场景里没有 ChaseLane 的跳过。

## 3. 实体

小人的身份是职业（role），决定外观、浮现的画面和帮助。怎么救靠摆放：直接照（怕黑）、先烧影藤（阴影缠）、先撞开裂纹墙（被困）、只有反射光照得到（玻璃拐角）、隔着栅栏照（关在笼子里）、两人同时照（结伴）。只有结伴、藏着的人、照不到的人需要专门的逻辑。

## 5. 存档

save_id = `<chapter_id>/<从章节根到该节点的路径>`，例如 `ch1/Level/Entities/Npc2`。顺着父节点拼出来，不依赖场景树。节点改名或移动会改变 id，发布后就别动了。

进度以 `Save` autoload 内存里的这一份为准，死亡和按 R 重载都不丢；从标题进来时按下面的时机写进 `user://save.json`（Web 上由 Godot 存进浏览器的 IndexedDB）：

```json
{
  "version": 2,
  "chapter": "ch2",
  "checkpoint": "ch2/Level/Checkpoints/CP1",
  "rescued": {"ch0/Level/Entities/Watchman": "watchman"},
  "mail": {"ch1/Level/Entities/Doctor": "doctor"},
  "broken": ["ch3/Level/Entities/Crack2"],
  "burnt": ["ch1/Level/Entities/Vine1"],
  "endings": {"main": true}
}
```

- `chapter` 是"继续"要进的章节，空 = 还没开始或刚看完结局。`checkpoint` 为空表示 PlayerStart。
- `rescued` 是 save_id → 职业。帮助按职业查：某个职业有没有人被救。
- `mail` 是等邮差的人（save_id → 职业）：照不到的人在自己那章加载时登记，邮差被救时这些人一起算已救。
- `endings` 记看过的结局，新游戏也不清。
- 写盘时机：进入章节、到达检查点、救人、通关、看完结局。烧掉的影藤、撞碎的墙跟着下一次写盘存下来。
- 测试把 `Save.path` 换成自己的文件，跑完删掉，不碰玩家的存档。
- 亮度上限不存，现算：`light_base + light_per_rescue × 已救人数`，不超过 `light_cap`。
- 内存里的集合用类型化 Dictionary（4.4 起支持）：`rescued` 是 `Dictionary[String, StringName]`，其他是 `Dictionary[String, bool]`（id → true）。
- 死亡或按 R：重新加载章节场景。各实体在 `_ready` 里查存档，直接切到最终状态（已救、已碎、已烧、门已开），不播特效。小星出现在检查点，亮度回满。小星星随重载重生。
- version 对不上就清档。

## 6. 进度

- 没有速度解锁。被救的人让亮度上限 +`light_per_rescue` 并回满，再按职业给一种帮助（第 7 节、状态机第 18 节）。
- 一个都不救也必须能打到正常结局：主线路上的小星星要够用，每段赛道开头有常亮加速带。做每一章时用通关测试验证。
- 隐藏线：ch2 救向导 → 藏着的人开始出声；ch3 救锁匠 → 所有铁门打开，掉头回本章开头救铁门后的邮差 → 邮差点亮 ch1 玻璃房里的医生；ch4 铁门后的笼子里是科学家。
- 隐藏结局 = 所有人都已救，一共 12 人。人数写成 `game.gd` 里的常量，测试检查它等于各章场景里小人的总数。

| | chase_respawn_speed | 600 | 追逐中复活时的初速（阶段 4） |
| 帮助 | help_slow_time / help_slow_mult | 2.0 / 0.5 | 钟表匠：噬光者减速几秒、速度乘多少 |
| | help_knockback | 400 | 乐手：噬光者沿轨迹往后退多少 px；守夜人的盾挡住一次接触时退一半 |
| | charge_time | 1.5 | 科学家：从掉头虫洞出来后一路冲回去多久（不听方向键，速度不变） |

## 10. 关卡与测试关

所有关卡都由 `tools/build_test_levels.tscn` 按文本地图生成，图例写在 `tools/build_test_levels.gd` 开头。生成的场景是章节结构（根上挂 chapter.gd，下面是 Level 和 ChaseLane），改地形改 `tools/` 下的 txt，不要在编辑器里改场景（下次生成会覆盖）。

正式章节一章一章接进 `game.gd` 的 `CHAPTERS`，接进去之前先用测试关把流程跑通。

地图里的数字 `1`–`5` 是提示牌（`scripts/entities/hint.gd`）：小星走进来，HUD 顶上浮出一行字，停 4 秒，只响一次、不挡路也不存档。文字在 `scripts/data/hints.gd` 里按 id 写，地图只管摆位。教学段用它说清楚操作，后面的章节能不用就不用——玩家不该靠读字过关。

地图改完跑一下 `python tools/check_maps.py`：它按小星的半径（10 px）在像素级上查连通性，能抓到"瞬移测试发现不了"的死缝——两头对不齐的走廊、被柱子夹死的 1 格缝；也会报"不该走进去却走得进去"的地方（玻璃房、笼子漏一条缝就废了）。影藤当成已经烧掉来算。

- `ch0_fall`（序章·坠落，已接进章节表）：地图 `tools/ch0_map.txt`，加暗处，守夜人一个人。出生房往东 4 格就是墙，按住方向键冲过去正好是阶段 2，撞一次扣 20 亮度——这一章就是用低价把"阶段 2 撞墙的代价"教掉；竖井里有一颗小星星补回来。全图没有加速带，WASD 最多到阶段 4，撞墙只反弹不碎。赛道 `tools/ch0_lane.txt`：常亮加速带、守夜人的路灯和盾。测试 `tests/test_ch0.tscn`。
- `ch1_vine`（影藤·聚光，已接进章节表）：地图 `tools/ch1_map.txt`，加暗处，园丁和医生两个人。走廊用一整道影藤封住，散射照不动，得聚光烧 1.5 秒；园丁封在壁龛里，壁龛口也是影藤，烧开才照得到他。医生关在小星进不去的玻璃房里：玻璃挡光，照不进去，他会在章节加载时把自己记进 `mail`，等 ch3 的邮差救。玻璃房的南窗和西窗能看见里面，哭声的声波圈也隔着墙看得见，所以找得到人、救不了。赛道 `tools/ch1_lane.txt`：园丁的花（一段加速带）、医生回满亮度。测试 `tests/test_ch1.tscn`。
- `ch2_mirror`（镜角·反射，已接进章节表）：地图 `tools/ch2_map.txt`，加暗处，画家和向导两个人。西房和东房之间是一道实墙，只有虫洞能过去（两端都是双向、保持方向）。画家蹲在 1 格宽的竖井里，井口用一块斜玻璃封住：小星挤不进去，正对着往下照也被玻璃挡住，只有站在西边把聚光打在那块斜玻璃上，反射光才会拐进竖井。向导窝在虫洞房西北角的凹角里，要绕进去才照得到。赛道 `tools/ch2_lane.txt`：画家的光门（单向虫洞捷径）、向导。测试 `tests/test_ch2.tscn`。
- `ch3_crack`（裂纹·被困，已接进章节表）：地图 `tools/ch3_map.txt`，加暗处，矿工、锁匠、邮差三个人。出生房北边一间小屋关着邮差，门口是铁门，开局打不开——先往东走。大厅里的加速带把速度推到阶段 4（620，不到阶段 5，免得把地图挖穿），撞碎通道上的裂纹墙才能过去；矿工在墙后。再往东是栅栏笼子，光进得去人进不去，隔着栏杆救锁匠；救到锁匠的当场，全图的铁门一起打开，掉头回出生房救铁门后的邮差。邮差一被救，ch1 玻璃房里记在 `mail` 里的医生跟着得救（`Game._on_npc_rescued` 处理），这就是隐藏线的前半段。赛道 `tools/ch3_lane.txt`：矿工的隧道（一大块墙中间穿过去，没救他就得从下面绕）。测试 `tests/test_ch3.tscn`。
- `test_feel`：移动和撞墙手感，地图 `tools/test_feel_map.txt`，不加暗处。赛道 `tools/test_feel_lane.txt` 没有人帮忙：闸门、裂纹墙、错开的柱子。已不在章节表里，留作手感调试场。
- `test_light`：光和各种实体，地图 `tools/test_light_map.txt`，加暗处，12 个职业都在。一种打法：守夜人 → 聚光烧影藤救园丁 → 玻璃窗后的医生照不到 → 烧影藤门 → 钟表匠、角落里的向导 → 潜望镜（拐角的斜玻璃挡住小星，只有聚光拐得过去）救画家 → 乐手和听众 → 检查点 → 长跑道冲到 4 档撞碎裂纹墙 → 矿工 → 隔着栅栏救锁匠，铁门打开 → 铁门后的科学家 → 虫洞回出生大厅 → 回头救铁门后的邮差，医生收到信 → 出口。一个都不救也能直接走到出口。已不在章节表里，但 `test_light_level` / `test_finale` 还拿它当多段赛道的样本。
  赛道 `tools/test_light_lane.txt` 里有各职业的帮助点：守夜人（路灯、盾）、医生、钟表匠、画家（光门跳过柱子阵）、园丁（花）、乐手和听众、矿工（隧道穿过一大块墙；没救他就从上面绕）。
- 终章：开头 `tools/finale_intro.txt`、结尾 `tools/finale_outro.txt`。`tests/test_finale.tscn` 里小星按路线自己跑两遍：一个都没救跑到逃离点；全救了一路有人帮，最后冲进科学家的虫洞撞碎噬光者。它把两张测试关固定成自己的章节表来测多段拼接；正式章节齐了以后改成直接跑 `Game.CHAPTERS`。

## 11. 速度靠地图

没有封顶，玩家能到哪一档只由地图决定。摆直道和加速带时参考下面的数（`accel` 420、`coast_decel` 90、`brake_mult` 3.5）：

| 从静止按住一个方向 | 速率 | 需要的直道 |
|---|---|---|
| 进入阶段 2 | 240 | 69 px，约 2 格 |
| 进入阶段 3 | 380 | 172 px，约 5.4 格 |
| 进入阶段 4 | 560 | 373 px，约 11.7 格 |
| WASD 最快（阶段 4 的顶） | 759 | 686 px，约 21 格 |
| 阶段 5 | ≥ 760 | 只能靠加速带、虫洞、黑洞 |

- 松手滑行掉档很慢：从 380 滑到 240 要 482 px（约 15 格），所以冲起来以后会在阶段 3 待很久。
- 反向按刹车：从 560 刹停约 107 px（3.3 格），从 380 约 49 px（1.5 格）。
- 斜着跑也算直道，大房间的对角线很长。不想让玩家到某一档，就别留那么长的直道，用柱子、拐角打断。
- 阶段 4 撞裂纹墙、阶段 5 撞碎一切，都靠地图控制在哪能出现。阈值（`stage_min`）可以按关卡需要调，调了要重新算这张表。
